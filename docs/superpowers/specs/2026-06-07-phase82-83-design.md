# Phase 8.2 & 8.3 Design: Contextual Vulnerability & Epistemic Drift

## 1. Contextual Vulnerability (Phase 8.2)

### Architecture & Data Flow
*   **Model Update**: Add `Opportunistic` to the `FactionStance` enum in `Models/Faction.cs`.
*   **Logic (GetSceneAsync)**: Instead of the engine attempting to score the party's vulnerability, we rely entirely on the LLM's natural language comprehension.
*   **Pressure Emission**: In `CampaignRepository.GetSceneAsync`, if any faction present in the scene has the `Opportunistic` stance, the engine will unconditionally emit a `Simulation` pressure. 
    *   **Prompt**: *"An Opportunistic faction is present. Evaluate the visual tags, current appearance, and item states of the characters. If they appear wealthy, exhausted, or otherwise vulnerable, narrate an attempt to exploit, rob, or ambush them."*

## 2. NPC Memory & Epistemic Drift (Phase 8.3)

### Architecture & Components
*   **Configuration**: Add `MemoryTrivialDecayDays` (default 20) and `MemoryImportantDecayDays` (default 40) to `CampaignConfig.cs`.
*   **Memory Models**: 
    *   Introduce `MemoryImportance` enum (`Trivial`, `Important`, `Core`).
    *   Create a `MemoryNode` class containing `Topic` (string), `Details` (string), `DayAcquired` (int), and `Importance` (MemoryImportance).
*   **Character Updates**: Replace the old `KnowledgeGraph` in `PsychologyProfile` with `public Dictionary<string, MemoryNode> Memories { get; set; } = new();`. (Breaking change; backwards compatibility not required).

### Data Flow
*   **Mutations**: Add a `knowledge_update` record inheriting from `WorldChange` in `WorldChanges.cs`. Include `CharacterId`, `Topic`, `Details`, and an optional `Importance` override.
*   **Handler**: Implement `KnowledgeUpdateHandler`. When processing an update, it creates or updates the `MemoryNode` and strictly sets `DayAcquired` to `CampaignTime.TotalDaysElapsed`.
*   **Decay Pressure**: In `GetSceneAsync`, iterate over all `Memories` of all NPCs present in the scene. Calculate age (`CurrentDay - memory.DayAcquired`). If age > threshold (based on `CampaignConfig` and `Importance`), emit a `Simulation` pressure instructing the LLM to use `knowledge_update` to let the memory decay (e.g., misremember details, fade, or become distorted). `Core` memories are exempt from decay.

## 3. Testing
*   Add `KnowledgeUpdateHandler` tests to ensure `DayAcquired` updates properly and memories are added/modified correctly.
*   Add unit tests in `CampaignToolsTests` to ensure decay pressure is emitted only when the threshold is passed.
*   Ensure the `LazyLlmScenarios.cs` harness can handle evaluating `knowledge_update`.
